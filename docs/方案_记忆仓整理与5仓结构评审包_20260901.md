## 2. 治理机制现状（摘自 AGENTS.md，评审前请实读该文件）

- **读写时机**：新项目单元开始才读；可交付单元完成/用户拍板/共享状态变化才写。
- **写入三件套**：CHANGELOG 追加流水；STATE 保留式整体重写（稳定 ID `[S-YYYYMMDD-NN]`，删除必须先在 CHANGELOG 记 `DROP`，pre-commit hook 拦截）；DECISIONS 只在拍板时追加（`[D-YYYYMMDD-NN]` + SUPERSEDES 链）。
- **Git 串行化防冲突**：`pull --ff-only` → 重读磁盘最新 → 保留式修改 → commit → push；禁止 reset --hard / force push；STATE 单写者。
- **生命周期**：STATE 超 60 行/12KiB、「已完成(最近)」超 8 条必须 rotate：`python scripts/rotate_memory.py`，旧内容原样进 archive/；STALE 只报告不自动删。
- **pre-commit hook**：条目数上限 / DROP 记录 / 凭证扫描（secret_scan.py）。

## 4. 实测痛点（2026-08-29 ~ 09-01 案例，全部实证）

- **P1 未提交改动归属不明**：截至本文写作，`git status` 实测有 3 处改动 + 3 处未跟踪留置多日：`M global/TOOLS.md`、`M projects/ai-resources/CHANGELOG.md`、`M scripts/gpt_wait_extract.mjs`、`?? global/runtime/`、`?? projects/ai-resources/plans/`、`?? projects/ai-resources/reports/`。多个 Agent 会话先后工作，coordination/claims 最新认领停在 C-20260830-02，**改动无法判断归属与就绪度，导致整理工作不敢带它们做 commit**。
- **P2 治理规则执行成本高**：2026-09-01 夜做 STATE 轮转时被 pre-commit hook 连续拦截两次（"9 entries (> 8)" → 补 DROP 后又拦 "DROP without record"），需追加 CHANGELOG 行才通过。规则正确但多线并行下 8 条上限偏紧，Agent 试错成本高。
- **P3 运行态数据入仓边界未落地**：GWS-3100 R2 决策「global/runtime/ 加入 .gitignore」尚未执行（.gitignore 实测无该条）；Sentinel 每分钟原子覆写 gateway-health.json、追加 alerts.jsonl → git status 常年脏 + 运行数据有被误 commit 风险。
- **P4 docs/ 与 global/ 边界漂移**：docs/ 已积 12+ 文件（一次性方案 / 转交语 / 问诊包 / SOP / ai-advice/ 子目录），常驻纪律在 global/TOOLS.md，项目状态在 projects/<id>/STATE.md——**同一层信息三个去处且无互链规范**，新会话不知从哪个读起、读完 docs 方案后纪律该落到哪。
- **P5 项目地图过时且双份并存**：见 §3 已知漂移。全景文档无「快照日期 + 复核机制」，与真源静默脱节。
- **P6 archive 双粒度并存 + 逐字膨胀**：archive/projects/<id>/2026/ 下按日文件与按月文件并存（如 devel-tools 同时有 2026-08-30.md、2026-08.md、2026-09-01.md），粒度规则未定版；全文逐字归档使热文件体积持续增长，检索靠人 grep。
- **P7 claims 机制覆盖不了系统级互斥**：2026-09-01 GWS-3100 提权切换窗口中，另一个 Claude Code 会话在秒级窗口抢占 :3100 端口导致 NSSM 服务 fail-closed 退出。记忆仓的 coordination/claims 管的是「记忆写入认领」，管不了「两个会话同时动生产端口/服务」这类系统级操作互斥。
- **P8 Windows/多 shell 环境坑未沉淀为结构化纪律**：git-bash 8bit 退出码截断（3102→30）、PowerShell 5.1 `Get-Date -UFormat %s` 时区偏移 6h（机器 TZ=Pacific Standard Time）、nssm get 输出 UTF-16、中文路径编码。这些坑每次踩都记在会话或项目 STATE 里，但**没有归口到 global/TOOLS.md 的结构化「环境坑位表」**，新会话重踩。
