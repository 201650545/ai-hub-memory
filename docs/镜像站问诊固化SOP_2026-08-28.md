# 镜像站问诊固化 SOP（2026-08-28 · 最快路径版）

> 目标：任何 Agent 拿到本文档即可用**最少步骤、最短时间**完成一次 GPT 镜像站问诊。
> 前置：opencli 可用；共享会话 n8hh7hyn 属于其他 Agent，**默认用独立会话 gptreview**（vip-12 已登录）。

## 标准流程（5 步，正常耗时 ~4 分钟）

| 步 | 动作 | 命令/要点 | 预期耗时 | 通过判据 |
|---|---|---|---|---|
| 1 | 确认会话在线 | node "D:\opencli-app\dist\src\main.js" browser gptreview state → URL 非 about:blank 即在线 | 5s | URL=vip-12.67673.live |
| 1a | （仅离线时）拉起 | browser gptreview open "https://vip-12.67673.live/" + sleep 10 | 15s | editor:true |
| 2 | 切 Extended | eval 点击 Auto pill 的 svg（pointer/mouse 五连完整事件序列）→ 等 3s → 点 [data-testid=model-switcher-gpt-5-6-thinking] → 验证 span Extended 存在 | 8s | {"extended":true} |
| 3 | 注入提示词 | PowerShell 读文件 → base64 → eval insertText 到 #prompt-textarea[contenteditable=true] → 校验 len 与尾部 | 5s | len>0 且尾行完整 |
| 4 | 发送 | eval 点 [data-testid=send-button]（disabled=false 才点） | 2s | "sent" |
| 5 | 等待+提取 | sleep 150s → 查 stop 按钮 + assistantCount → 提取 last.innerText 存档 | 150s | len>0 非空 |

## 快速检查清单（发送前 10 秒过一遍）

- [ ] 提示词是否**内嵌**了所有 GitHub 链接内容（多链接=Deep Research 空回复）？
- [ ] 是否含验证令牌要求（强制 GPT 实读 GitHub）？
- [ ] 轮次：本任务 ≤3 轮？本窗口累计 <12 轮？
- [ ] 凭证检查：提示词里无 key/token/JWT？
- [ ] JSON 注入用文件路径而非 PowerShell 直传？

## 故障处置（每步的异常出口）

| 症状 | 判定 | 处置 |
|---|---|---|
| state 报 Browser Bridge not connected | 桥断 | 让用户在 Chrome 重载 opencli 扩展；或 daemon restart 后等 30s 重试一次 |
| 页面 about:blank | 会话空 | browser gptreview open https://vip-12.67673.live/ + sleep 10 |
| Auto pill 找不到 | 未登录/页面未加载完 | state 看 URL；重 open；再不行换账号重登（问达宝读 panelAccountList → localStorage authToken → plus-login URL） |
| 发送后 assistant 0 字（连续 2 次） | 实例故障 | **报告用户**：现象+已试账号+建议，不自动兜底（D-GLOBAL-20260828-01） |
| eval 报 Target tab not part of session | 标签失效 | tab new "URL" 开新标签拿新 target id；绝不复用旧 id |
| GitHub 内容对不上 | 页面缓存 | 汇报附 commit 短 SHA + raw.githubusercontent.com 直链 |
| PowerShell 传中文 JSON 乱码 | 编码 | --json @相对路径.json（UTF-8 无 BOM，先 cd 到目录） |

## 台账字段（每次问诊记录到 devel-tools STATE）

- 字段：SID、日期、会话（gptreview/vip-12/新窗口第 N 轮）、提示词文件路径、GPT 结论摘要、验读令牌值、存档路径。
- 负责人：当值 Agent。
- 检查频率：每次问诊后即时写；每阶段结束核对 STATE 与实际文件一致性。
- 异常处理：按本文「故障处置」表；处置结果写进当日 STATE 条目。
- 团队检查方式：STATE 条目 ↔ 存档文件逐条对照，任何人可抽查。
