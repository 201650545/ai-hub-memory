## 一句话背景
本机 :3100 LLM 转发网关（仅监听 127.0.0.1，loopback，带 Bearer key）。实测发现「对外可见模型名」与「可路由模型」有意不一致（渠道策展只约束暴露面、按名调用不受限），结果 190 个可见名中 12 个会路由到收费款（某渠道 166 款仅 5 款真免费）且准入 eligible=True → 用户随时意外扣费。网关现在**完全没有 per-model 定价数据源**（billing_type 是渠道级硬编码且已被证伪、free_models 字段只进健康展示、路由判定序里无价格项）。

## 方案骨架
1. 新定价真源 `model_pricing.json`：`class ∈ {free,paid,unknown}` + 渠道级 `default_class` + 全局兜底 + `verified_at`（30 天降 unknown；配额型条目标 `account_bound` 用 7 天）。默认收紧、白名单放行。
2. 准入判定序插入 `pricing_gate`：现状 `disabled → no_key → unreachable → capability_mismatch → blocked → quota`，新序把它放在 capability 后、blocked 前。free→放行；paid→拦；unknown→拦。候选被拦则继续 failover 下一渠道，全链被拦→整体 403。
3. 授权：全局 `API_GATEWAY_ALLOW_PAID=1`=观察模式（记日志不拦）+ 条目级 `authorized`。定价文件解析失败→启动退出码 3106（fail-closed）。
4. 编排组（人工逐款实测过的免费组）展开**不经**价格判定=白名单，仅在写入组成员时校验一次价格防破口。
5. 上线路径：P1 手工灌已实测数据 → P2 观察模式跑真实流量 ≥3 天 → P3 强制 → P4 扩回归测试（现有 35 例基线）。
