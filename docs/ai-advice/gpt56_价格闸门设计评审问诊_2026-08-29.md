## 1. 背景与实证（全部 file:line 已复核）

### 1.1 扣费路径事实
网关对外模型列表与可路由模型集合**故意不一致**：

- 对外列表应用渠道策展：`channels.py:1320-1326`——注释原文「渠道模型策展：已选列表存在时，**对外只暴露已选（详情页仍可看全量、按名调用不受限）**」。
- 路由解析用**全量在线目录**：`channels.py:1426-1435` `model_providers` 包含搜索遍历 `st["models"]`（来自 `channel_health` `channels.py:893/896`），不读 `channel_models.json` 的 selected。

后果（S-20260829-05 实测）：190 个可见模型名中 **12 个**会解析到 zenmux 收费款且 eligible=True（claude-sonnet-5→anthropic/claude-sonnet-5、gpt-5.6-sol→openai/gpt-5.6-sol、glm-5.2、hy3、mistral-large-2512 等）。zenmux 166 款中仅 5 款真免费，其余 161 款收费。

### 1.2 现有价格语义为什么兜不住
| 现状 | 位置 | 问题 |
|---|---|---|
| `billing_type` 渠道级硬编码 | `channels.py:48-250`（zenmux 整体标 `free`） | 渠道级标签在 zenmux 上**已经错了**（161/166 收费），不能作放行依据 |
| `_channel_sort_key` 免费优先 | `channels.py:1273` | 只影响**排序**，不做**拦截** |
| `free_models` 字段 | 写入 `channels.py:126`+custom_channels；唯一读取 `_augment_health` `channels.py:940` | 只进健康展示（`/api/channels`），**路由/准入零引用** |
| `rate_limit._is_free_model` | `rate_limit.py:86-88` | 按 `:free` 后缀猜，仅用于分桶 |
| 上游价格 API | 全仓 grep `pricing/price/cost` **0 命中**（仅 `get_balance` `channels.py:767-815` 探余额展示） | 网关**没有任何 per-model 价格数据源** |

启发式不可靠的反例（本机真实配置）：`unified_models.json` 的 deepseek-free 成员 `modelscope: deepseek-ai/DeepSeek-V4-Pro-0813` 名字带 Pro 但在魔搭走积分、积分用完直接不可用而不产生账单；openrouter 成员带 `:free` 后缀但同名的非 `:free` 款收费。**闸门必须基于逐渠道逐模型的已验证定价事实，而非名称猜测。**

### 1.3 准入判定序（闸门插入点）
`api_gateway.py:482-493`（`build_route_plan`）：`disabled → no_key → unreachable → capability_mismatch → blocked → quota`，**无价格项**。能力层哲学（`capabilities.py:129-138`）：仅显式 False 才阻断、未知默认放行（fail-open，向后兼容）。
真实转发唯一入口准入：`api_gateway.py:341` `check_candidate`；`chat_completion` 直连路径 `channels.py:1166` 在 `api_gateway.py:358` 换上游真名后 POST——**闸门加在准入序即可覆盖全部转发路径**（管理端点 smoke 亦走同链）。

## 2. 目标 / 非目标

**目标**
- G1：任何解析到「已验证收费」上游模型的直呼请求，默认不产生转发（消除意外扣费面）。
- G2：「未验证定价」的模型默认不放行（计费面 fail-closed，对齐 wildcard 门先例），可用显式授权放行。
- G3：编排组（fast / deepseek-free）既有调用**零误伤**，回归可证。
- G4：定价数据有唯一真源、可维护、可溯源（记录验证时间与证据），不复制飞书 Base。

- 不做配额/预算管理（余额监控、月度上限另案）。
- 不改「按名调用不受限」的策展语义（见 §3 方案对比；那是另一个决策）。
- 不做自动降级到免费等价模型（Q3 已拍板：不静默降级，见 §7）。
- 不动 :3000 聚合网关。

## 4. 设计

### 4.1 定价真源：`model_pricing.json`（新文件，`D:\项目\data\search_gateway\`）

```json
{
  "version": 1,
  "channels": {
    "zenmux": {
      "models": {
        "dots-studio/dots3-note-prev": {"class": "free",  "verified_at": "2026-08-28", "evidence": "S-20260829-05 pricings 逐款核算"},
        "anthropic/claude-sonnet-5":  {"class": "paid",  "verified_at": "2026-08-28", "evidence": "S-20260829-05"}
      },
      "default_class": "paid"
    },
    "modelscope": {"models": {"deepseek-ai/DeepSeek-V4-Pro-0813": {"class": "free", "billing_model": "quota", "account_bound": true, "verified_at": "2026-08-29", "note": "名称含 Pro，魔搭积分制：积分用完直接不可用、不产生账单"}}, "default_class": "unknown"}
  },
  "global_default_class": "unknown"
}
```

- `class ∈ {free, paid, unknown}`。分类标准（Q1 已拍板）：闸门语义定义为「**合规使用下不产生账单**」——超额后仍会出账的算 `paid`；额度/积分用完只是**服务被拒而不会产生账单**的算 `free`。
- 配额型（魔搭积分、nvidia 免费 credit 等）归 `free`，但必须显式标注 `"billing_model": "quota"` + `"account_bound": true`：**这类"免费"是当前账号的状态，不是渠道的属性**——充值、换 key、活动到期都可能翻转。对 `account_bound` 条目使用更短的复核窗口（`QUOTA_STALE_DAYS`，默认 7），过期降 `unknown`。
- 每渠道 `default_class` + 全局 `global_default_class` 兜底。已知收费大户（zenmux）渠道级默认 `paid`，新上架模型天然落入被拦侧，需验证后才升级到 free——**默认收紧、白名单放行**的不对称设计。
- `verified_at` 超 `PRICING_STALE_DAYS`（默认 30，可配）自动降为 `unknown`（对齐 TOOLS.md §6.5 新鲜度纪律：陈旧不用）。
- 数据维护：初期**手工实测登记**（来源即 S-20260828-01 / S-20260829-05 已精测的结论），后续可选上游 pricings API 拉取器（`rate_limit`/健康缓存同款 mtime 热载 `_cached_json` `channels.py:264-281`，改文件免重启）。
- 读取路径唯一真源：本 JSON。**不把价格写进 channels.json 的 free_models**（该字段维持现状仅作展示，避免双真源；是否废弃留待后续清理，见 Q4）。

### 4.2 判定：准入序新增 `pricing_gate`

`build_route_plan` 判定序变为：`disabled → no_key → unreachable → capability_mismatch → pricing_gate → blocked → quota`。

- 置于 capability 之后：能力不符的候选连查价格的必要都没有；置于熔断/限流之前：**熔断是运行时保护，闸门是静态属性**，先静态后动态，reason 归因清晰。
- 判定函数（新，建议 `pricing.py` 与 `capabilities.py` 同层同风格）：
  ```
  verdict(channel_id, upstream_model) -> {allow: bool, class: str, reason: str}
  ```
  - `class=free` → allow。
  - `class=paid` → **deny，除非显式授权**（§4.3）。
  - `class=unknown` → 按 `PRICING_UNKNOWN_POLICY` 处理（**默认 deny**，fail-closed，Q2 已拍板）。
- 候选被 deny 时：从候选链剔除、继续下一渠道（failover 语义不变）；**全链皆被 deny → 请求整体 403**（Q3 已拍板，不做静默降级），错误体 `{"error": {"type": "pricing_gate", "code": "model_pricing_blocked", "model": <请求名>, "reason": "class=paid|unknown"}}`。
- 与 Q1 的配合：配额型渠道（魔搭积分等）积分耗尽时是**上游返回错误**而非产生账单，闸门放行后由现有 failover/错误处理自然承接，不需要闸门参与额度判断。
- 编排组展开（`load_unified` `channels.py:603`）**不经价格判定**——组成员由人工登记并逐款实测（先例 S-20260828-01③），组即白名单；但 `POST /api/unified`（`channels.py:617` `set_unified_model`）**写成员时执行一次价格校验**：新成员 class≠free 且无授权 → 拒绝写入（400），防止将来有人往组里塞收费款把白名单破口重新打开。

### 4.3 显式授权门（完全复刻 wildcard 门先例，S-20260829-15）

- 全局开关：环境变量 `API_GATEWAY_ALLOW_PAID=1` → 闸门进入**观察模式**（记日志不拦截），供确需付费调用的场景；缺省=强制模式。NSSM 服务改环境变量需提权脚本配合重启（脚本库 `.tools\`，同服务注册先例）。
- 按模型授权（ finer ）：`model_pricing.json` 的条目加 `"authorized": {"by": "user", "at": "...", "note": "..."}` → 该条 paid 模型放行且日志标 `authorized_paid`。授权只增不删、可审计。
- 配置错误 fail-closed：`model_pricing.json` 存在但**解析失败** → 启动退出码 **3106**（Q5 采纳建议：避开告警事件源 ID 3105 的命名空间，与 3102/3103/3104 同族），NSSM 映射 Exit 不 crash-loop；文件缺失 → 等价于「全部 unknown」，按 Q2 拍板结果默认 deny（观察模式下恒 allow + 记日志）。

### 4.4 可观测性
- 路由日志（`api_gateway.py:323-332`）新增：`pricing_gate: {evaluated: n, denied: [{channel, model, class}]}`；403 全拒时 `errors` 带 `pricing_gate` 类型（上限 200 条沿用现制）。
- `GET /api/health`/`/api/channels` 增补渠道级定价覆盖率（free/paid/unknown 计数），前端展示后人类一眼看出「哪些还在裸奔」。
- 响应头 `X-Routed-Channel` 家族增补 `X-Pricing-Class: free|paid|unknown|authorized_paid`。

### 4.5 与告警/审计联动（可选项 P3）
拦截事件计数超阈值（如 1h 内 >10 次同模型）→ 复用 watchdog 告警文件家族（`failclosed_alerts.log` 同款新增 `pricing_gate_alerts.log`），防「客户端配置错了在疯狂撞墙」。默认不做，评审定。
