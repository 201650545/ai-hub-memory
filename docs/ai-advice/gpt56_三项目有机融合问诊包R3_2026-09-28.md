**Q2 `类型` 值域被写者破了。** 设计文档的值域是单值（workaround/pitfall/user_correction/fact/preference），实测有 2 条写成 `workaround / pitfall`、3 条整字段不填。**多值是该允许（那就改值域并定义优先级）、该禁止（那写者要当场拒），还是该由提炼器裁定？** 这条直接决定我下一步是写「写者规范闸门」还是「值域扩展」。

**Q3 `frozen` 在冻结 `task.schema.json` 的 7 值里没有位置。** 看板原生只有 6 个状态词头（完成/已冻结/待验收/进行中/待办/冻结 → done/frozen/pending_acceptance/in_progress/todo），而 task Schema 是 queued/active/blocked/completed/failed/cancelled/superseded，experiment Schema 只有 planned/running/completed/cancelled（连 `todo→queued`、`in_progress→active` 都不收）。真树为此红 3 条。三条路我都看到了：改 Schema（30_ 冻结，不可）、加映射层（等于编造语义，我不做）、裁定 `frozen` 属生命周期之外的第三态。**请裁定，并给出第三态在 Schema 层怎么表达而不破坏「四份 Schema 冻结」这条规则。**
