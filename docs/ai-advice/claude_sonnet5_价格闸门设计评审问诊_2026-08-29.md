## 一句话背景
本机 :3100 LLM 转发网关（仅监听 127.0.0.1，Bearer key 鉴权，多上游渠道 + 免费/收费混合）。实测发现：「对外可见模型名」与「可路由模型」有意不一致（渠道策展只约束暴露面，按名调用不受限），导致 190 个可见名中 12 个会解析到收费款（某渠道 166 款仅 5 款真免费）且准入 eligible=True → 用户随时可能意外扣费。网关目前**没有任何 per-model 定价数据源**。

## 方案骨架（细节见链接）
1. 新定价真源 `model_pricing.json`：`class ∈ {free,paid,unknown}` + 渠道级 `default_class` + 全局兜底 + `verified_at`（30 天降 unknown；配额型条目 `account_bound` 用 7 天）。默认收紧、白名单放行。
2. 准入判定序插入 `pricing_gate`：现状 `disabled → no_key → unreachable → capability_mismatch → blocked → quota`，新序插在 capability 后、blocked 前。free 放行 / paid 拦 / unknown 拦；候选被拦继续 failover 下一渠道，全链被拦 → 整体 403。
3. 授权：全局 `API_GATEWAY_ALLOW_PAID=1` = 观察模式（记日志不拦）+ 条目级 `authorized`；定价文件解析失败 → 启动退出码 3106（fail-closed）。
4. 编排组（人工逐款实测过的免费组）展开**不经**价格判定 = 白名单，仅在写入组成员时校验一次价格防破口。
5. 上线路径：P1 手工灌已实测数据 → P2 观察模式跑真实流量 ≥3 天 → P3 强制 → P4 扩回归测试（现有 35 例基线）。

## 已由用户拍板、请勿重开（只评落地形态与副作用）
- Q1 「合规使用下不产生账单」即 free（积分/额度型渠道耗尽表现为服务被拒、不出账，由现有 failover 承接）；此类条目标 `account_bound` 并 7 天短复核。

- Q5 配置解析失败退出码 3106。
