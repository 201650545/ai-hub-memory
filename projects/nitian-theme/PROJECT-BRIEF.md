## 0. 一句话定位

**把"写代码"活成《仙逆》里王林的修道一生**：在本地 DeepSeek Harness（DSH）网关上做一个「轻量修真养成游戏引擎」主题插件——coding 行为流是事件源，Token 累计消耗是修为（人生刻度），27 个境界节点是人生里程碑。它**不是**一张换色皮肤，而是有叙事、演出、角色、数值的游戏引擎。

## 1. 载体与先例（"DeepSeek 先例主题插件"指什么）

- **DSH = DeepSeek Harness**：本机网关 `127.0.0.1:3080`，web 界面，日常在 Chrome 里用，是 AI 编程会话的操作台。
- DSH 全部 UI 基于 `--dsw-*` CSS 自定义属性，覆盖根色值即可驱动全局变色——这是"主题插件"可行的技术前提。
- **先例一（换肤通道）**：社区项目 `deepseek-skin-studio` 用 theme.json + CDP 注入实现零侵入换肤试跑，稳定后可打包为 DSH 原生插件。本项目沿用这条通道（先 CDP 试跑，再原生插件）。
- **先例二（数据源）**：社区已有 DSH 实时 Token 统计插件，证明引擎所需的 Token 用量数据可读。
- 所以本项目 = 在"DSH 主题插件"这条被验证过的路线上，做到前所未有的深度：不是换色，是整个游戏引擎。

## 2. 产品本质：修道 × Coding 的映射

三条设计法则：**线性对应**（故事节点 ↔ coding 数据一一锚定）、**真实沉浸**（动画截图/写实立绘的"动态电影海报"质感，拒绝卡通风）、**全链路演出**（境界是仪式，不是数字）。

核心事件映射（引擎层的灵魂）：

| Coding 事件 | 仙逆世界事件 | 呈现 |
|---|---|---|
| Token 累计到达节点 | **破境** | 全屏演出 + 换装 + 换场景 + 判词 |
| 报错 / 重试 | **遇敌受挫** | 该境界强敌浮现 + 经典台词 |
| 长时间无输出 | **闭关推演** | 角色打坐、灵气涟漪 |
| 工具调用 | **施展法宝** | 剑光/符箓/神游动效 |
| 任务完成 | **杀敌夺宝** | 仙玉入账、胜利闪光 |
| 上下文将满 | **灵力将竭** | 警示涟漪 |

界面命名体系（沉浸式文案）：侧栏会话=洞府、对话区=论道（回复=道音）、详情栏=道藏、输入框=传讯玉简、报错=心魔劫。状态栏三仪表：境界徽章｜灵力条｜仙玉余额。角色五态状态机：待机/思考/施法/受挫/突破。情绪设计：顺境平静陪伴、逆境激发斗志、高潮仪式感拉满——**用户即是王林**。

## 3. 成长线与数值骨架

- **27 个境界节点**（产品口径）：4 大境界（元婴、问鼎、碎涅、踏天一桥）+ 23 个小境界；Token 阈值按对数节奏（0–100K 凝气期 → 800M–1B+ 踏天九桥），跑一段时间后按真实用量一键重校准。
- 灵力条形如「元婴期 · 灵力 8.2M/20M」，累计只升不降。
- 测试闸门：`localStorage.nitian.demoTokens` 可注入演示用修为；测试完毕必须复位 `3999700000000`。

- 插件包 `nitian-dsh-theme` v0.2.0（`pkg/package.json` 声明 `dsh.client.platform=web, immediately`，即随 DSH web 端即刻加载）。
- 引擎 `lib/client.js`：`enter(i)` 境界切换状态机——**大小境界分化**（大境界=全屏破境视频+粒子雨+9s 清场；小境界=2.8s 轻演出）、面板跳跃选择器、localStorage 状态持久化（`nitian.demoTokens` / `nitian.opts.v2` / `nitian.splashSeen`）、资产基座 `/nitian-assets`。

## 5. 当前议题：仙逆故事知识库（飞书多维表格）

- 动机（用户原话大意）："要做好这个产品，应该对这个故事有很深的理解——不，先不说很深的理解，我们应该非常熟悉它才对。"
- 载体：飞书多维表格「仙逆故事知识库」，**单表**设计，9 字段（名称/类别/所属阶段/内容描述/原文摘录与台词/产品用途/来源/状态/备注），已灌 30 条种子（24 境界卡 + 6 实体：王林、许木分身、天逆珠、百万人头塔、踏天桥、轮回树）。
- 用户倾向：所有信息放一张表，不拆人物表/法宝表/事件表。
- 已获一轮 ChatGPT Extended 评审：支持继续单表，建议升级为"单主表+自关联"（加剧情序号/章节定位/关联记录/关系摘要/重要度 S-ABC，改"所属阶段"→"主境界节点"、"状态"拆语义），方法论=顺读+事件卡、两轮制、待整理≤30 条。**待用户拍板后执行。**

## 6. 工作方式（与 AI 协作的规矩）

- 单人 + 多 Agent 派工：Gemini 检索、TRAE 生图/生视频、本地脚本加工、主 Agent 架构与主笔；用户只做审美拍板与决策。
- **设计闸门**：设计 → 外部模型评审 → 用户拍板 → 逐次授权才动代码；评审未过零代码改动。
- **示例先行**：先出 3 条大境界真人风样片验收，通过后再批量生产。
