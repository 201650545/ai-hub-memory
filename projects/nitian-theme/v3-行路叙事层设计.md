## 3. 事件源：案 A 先行 + 事件适配层（评审重点①，已裁定）

v2.8 只监听了"报错"。工具调用 / 长推理 / 任务完成三个事件源缺失。

- **案 A（纯前端 observer）**：扩展现有 MutationObserver，按节点 class/文本特征识别工具调用块、thinking 态、任务完成徽记。零后端改动，当天可上；识别精度受 DSH 前端 DOM 结构约束。
- **案 B（server 事件流）**：`pkg/src/index.ts` 增加事件 hook → `/api/nitian/event` 落盘 → 客户端随 poll 顺带读取。事件可靠、语义精确；但要动 server 侧代码（单独授权）且依赖 Harness 是否暴露生命周期钩子（未知数）。

**裁定：A-first 通过，但 A 与 Journey 系统禁止直接耦合。** 必须先定一个薄事件适配层：

```
DOM Observer（A）──┐
                  ├→ 标准事件 → Journey 回响系统
Server Hook（B）──┘
```

**标准事件契约（Event Adapter Contract，S3 前冻结）**：
- 事件类型：`error / tool / thinking / task_complete`
- 事件载荷：`{ ts 发生时间, fingerprint 指纹, sourceKey 探针标识, realmId 当前境界节点 }`
- 未来 A 换 B，只换"探针"，不重写 doom、法宝回响、打坐态和痕迹系统。

**升级条件（替代原"跑两周"）**：样板实测后，按关键事件的误报/漏报是否明显决定是否升级 B。单人项目不写死时间。

**A 案口径收紧（防误报）**：
- `thinking`（打坐态）= **AI 回合已开始、但持续无有效输出**，不是用户页面静置 45s（正常看代码不得误判为闭关）。
- `task_complete` 只认明确的 DSH 完成态/徽记；DOM 没有可靠完成信号时**宁可不触发，也不从普通文本里猜"完成/done"**。

## 4. 数据结构：chronicle.json 扩展（引用化 + Effect 白名单）

现有键（events/enemies/treasures/friends/scene/eggs/quotes/era）回答"仙逆故事是什么"，保持不动。新增两节回答"怎么把故事讲给正在 coding 的用户"：

**Canon 稳定 ID（S1 第一步，现在是最便宜的补 ID 时点）**：S1 时给 04/05 两个阶段的 events/enemies/treasures/friends/quotes 条目补稳定 `id`（如 `en_04_01`、`qu_04_03`、`tr_04_shalu`）；24 阶段铺量时同规则跟进。**journey 只存引用，不复制 Canon 内容**——名称、语录、来源改错字时 journey 永不产生第二份旧数据。

**Effect 白名单（防 if/else 搬进 JSON）**：vfx 只允许以下有限可复用类型，每个 Beat 只声明 `type + asset 引用 + 强度`；新类型需设计评审进白名单，**禁止境界级随手发明新字段**（fog_density / moon_crack 之类一律拒绝）：

| Effect 类型 | 语义 |
|---|---|
| `bg_swap` | 背景替换/渐显 |
| `char_in` / `char_out` | 角色/剪影出现或退场（`temp:true` 表示叙事临时展示，不改用户角色选择） |
| `ui_intensity` | 界面强弱变化（海报压暗、卷轴边角点亮） |
| `particle_level` | 粒子强弱 |
| `seal_pulse` | 境界印/徽记呼吸 |
| `crack_glow` | 纹路/裂纹点亮 |

## 5. 四进度窗（元婴期具体化）

窗口只由 **当前境界 Token 进度 pct** 驱动（内部导演参数，不展示给用户）：

| 窗口 | pct | 世界变化（永久感） | 用户感知 |
|---|---|---|---|
| 入世 | 0–30% | yuanyingCG 背景渐显替代通用底；era_04 分身立绘入场；时代名浮现 | "到了新地方" |
| 因起 | 30–65% | 卷轴边角点亮人物/法宝标签；远处云天宗剪影 | "这卷故事在展开" |
| 劫至 | 65–90% | 敌人池切换为藤家系；海报压暗频率上升；语录偏移到复仇线 | "要变天了" |
| 临界 | 90–100% | 常驻克制异象：境界印呼吸加快、仙玉环微震、裂纹微光 | "马上破境"但**不弹窗、不遮代码、可正常干活** |

红线：修为只升不降 ⇒ 世界只向前。窗口跃迁不可逆，离线多天后恢复 = 直接落在当前 pct 对应窗口，不重放。

**状态与演出分离（评审新增）**：
- 世界状态永远可由 `realmId + pct` 直接重建；一次性演出（30% 闪一下、65% 标签点亮）只响应**活跃 Session 内的实时跨窗**。
- 一次 poll 跨多个阈值（如 29%→67%，或关机三天 20%→92%）：**直接落最终世界状态，最多播放最新一次轻转场，不连续补放三段动画**——杜绝"回来打开插件被昨天错过的三套特效轮番轰炸"。

**角色偏好隔离（评审新增）**：Journey 可临时展示叙事角色/剪影（`temp:true`），但**不能改写用户的本尊/分身选择**。"世界导演状态"与"用户角色偏好状态"隔离，二者各存各的。

**痕迹系统 v3.0（评审裁定：做视觉闭环，不做永久实名）**：

```
error fingerprint（标准事件提取，非显示文本比较）
→ 首次命中建立 trace，固定映射一个敌人剪影
→ 后续同源报错强化同一 trace（同一剪影累积出现）
→ 任务解决（该 fingerprint 消失/收到完成信号）→ 剪影碎裂 + 一次短暂揭名/提示
```

- "连续 3 次"阈值保留；"同源"定义 = 标准 `fingerprint`（如归一化报错类型+模块），**不是**比较显示文本（行号变化/不同任务同文本的歧义由此消解）。
- **v3.0 不改写编年史**：剪影碎裂后只有视觉层揭名一瞬，不落"？？？→永久实名"。"反复纠缠→最终解决→碎裂"的爽感先验证；永久解锁（Narrative Unlock State：跨刷新/跨 Session 的叙事解锁存档）模型定义清楚后 v3.1 再上——避免为一个 1.5s 的惊喜在样板里顺便造半套成就/存档系统。
- **chronicle.json 永远只读**：Canon 事实、导演配置、用户历程三种数据永不回写混入。
