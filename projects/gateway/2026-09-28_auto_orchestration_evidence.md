## 1. 系统事实

- OpenAI 兼容多渠道路由网关，本机 Windows + nssm 服务 `ai-gateway-3100`，Python 标准库、无外部依赖。
- 编排真源 `data/model_routes.json`（schema v2）：**16 条链 / 69 条目 / 49 唯一 (渠道,模型) 对**。
- 现行免费两线（2026-09-28 两线重构，旧三线 hidden 兼容至 10-05）：
  - `free-high` 8 席：静态键序 = 能力带 → success_rate → tok_s，能力门槛 ≥S2；
  - `free-flash` 14 席：静态键序 = 能力门槛 → success_rate → TTFT → tok_s。
- 客户端把 `model` 发成链名（`free-high`/`free-flash`）即走该链；`fallback_policy.enabled=false`，回落完全靠 members 顺序逐个试。
- 运行时对静态顺序只做三类动态改写（**没有按分数自动重排，这是本次要设计的空缺**）：
  1. `catalog_routes.healthy_members`：渠道停用 / 模型级冷却 / 故障域熔断 → 剔除；429 退避中 → 平移到池尾；
  2. `fault_domains.promote_on_proxy_down`：代理挂时把直连热备渠道升到链首；
  3. `quota_guard.blocked` 预过滤：额度警戒或非白名单整段剔除并留痕。
- 失败回写：`mark_member_cooldown(cid, real_model)`，冷却期内下次请求直接跳过该席。

## 4. 硬边界（这些不是策略参数，不可被设计推翻）

1. **付费禁测红线**：`deepseek / opencode / tokenrhythm / zenmux / ark-coding` 渠道与 `paid-fast` 全链**绝不发任何 API 请求**；网站审查只看不调。任何"自动接入/自动测"都不能把席位放到这些渠道上。
2. **封存渠道**（注册表 `get_sealed_channels()`）不探测、不接入。
3. **收费判定权威**：OR 目录 `pricing` 递归摊平后**全部数值字段为 0** 才算免费（含推理/缓存/图像/音频与 `overrides` 阶梯价；`min_prompt_tokens` 这类阈值字段除外；`-1` 视为非 0）。标价 0 但实测扣费的"伪免费"（如 `thinkingmachines/inkling` 家族、`openrouter/*` 路由伪模型）走显式禁碰名单，且禁碰名单必须同时作用于**运行时放行面**（今天刚补的漏洞）。
4. **能力筛选线**：AA 智能指数 ≥28 为过线；过线但只有付费档的模型一律不接（郭老师裁决）；U 档（无 AA 分、靠社区口碑）初判须 ≥3 独立来源方向一致，且只给临时能力带、禁当首席，7 天内用 perf 复核。
5. **编排写入唯一入口**：备份 → mutator 返回 `list[str]` 契约校验 → JSON 校验 → 原子写 → `healthz` 且 `loaded_routes_sha256` 与写入字节指纹一致 → 否则自动回滚 → 审计行。
6. 密钥绝不入仓、不入文档。
7. 隐私标注席位（如 `stealth/space-bunny-alpha`，社区多源标注 prompt 可能被匿名第三方保留）：敏感请求不应路由到它 —— 请设计"敏感/隐私席位"的隔离语义（例如只作末位兜底或按请求标记跳过）。

## 5. 已拍板、不可推翻的既有裁决（设计须与之兼容）

- **判定表**：目录查无 / 404 = 删除；429 / 5xx / 401 = 保留（限流不是死席）；**拿不准 = 保留**。
- **OR 目录缺失单次即摘**（郭老师裁决，覆盖 GPT 此前"连续 2 次缺失才动"的宽限建议）；理由：OR 目录 API 是全量权威清单（用 `total_count` 校验防分页遗漏）。
- **探针 429 与目录缺失是两个独立信号**，不得合成一个"失败"。
- 探针链路必须与运行时链路一致（同源代理、同 UA）——此前强制直连造成三席连续 5 天假故障。
- 每日摘要留 `data/`，不进主 Git（Git 只存配置、决策与自动安全摘除的证据）。

## 6. 要设计的东西（请逐条给明确规则，不要列原则）

1. **每日决策流程**：00:23 探针 + 12:00 目录刷新各自产出什么中间判定、什么时刻统一做一次编排决策、每天最多改几条席序/几个席位（防抖动与防一次性大改）。
2. **调序规则**：`free-high` 与 `free-flash` 各自的目标函数与键序；指标的最小样本量门槛（结合 §3 真实 n 分布给具体数字）；TTFT 与 tok_s 在不同链的权重；success_rate 如何与"上游 429"区分后再入分；新席观察期长度与观察期内的位置约束（现有约定：尾部观察 3 天）。
3. **防抖**：已升过/降过的席位多久可再次被移动；同席位多指标冲突时的优先级；如何避免 A→B→A 来回横跳。
4. **增席规则**：新达标免费模型进哪条链哪个位置、一次最多几个、能力带与现有首席冲突时怎么办、伪免费与禁碰如何兜底。
5. **删/替规则**：目录查无即摘（单次）；429/5xx 长期不通的处置上限（保留但降尾？保留多少天后升级处理？）；摘除后由谁补位（从候选池取的排序规则）。
6. **替换规则**：某席被摘后是否允许自动引入替代品、替代品的资格条件与位置继承。
7. **证据分型表**：`OK / RATE_LIMITED / MODEL_NOT_FOUND / AUTH_OR_POLICY / CONTRACT_ERROR / UPSTREAM_ERROR / TRANSPORT_ERROR / LOCAL_POLICY_SKIP / NOT_DUE` 的判定输入（外层 HTTP + 内层结构化 provider error 的优先级），以及每类允许触发的动作集合。
8. **失败与安全**：自动改动后如何被发现改坏了（探针首轮实测、日报指标、一键回滚入口）；什么情况下自动执行应当**停下来只报警**（例如一次要动超过 N 席、perf 数据当日缺失、OR 目录抓取失败、闸门异常放行）。
9. **给人看的形态**：郭老师随机出现时应该在哪个页面/文件、看哪几行就能明白"昨天自动做了什么、为什么、当前两线长什么样"。

## 7. 约束（工程与人的）

- 单机、Python 标准库、无数据库；状态都在 `data/*.json`。
- 探针预算有限（免费渠道各有日预算与限流），策略不能靠"多打请求"获取信息；每天每渠道探测次数有闸。
- 每个自动决定都必须可解释（能引用到具体数字与样本）、可回滚（有备份与审计行）。
- 实现要能分刀落地：请给出"今晚就能做的最小版"与"需要补数据/补身份后才能做的完整版"两档。
