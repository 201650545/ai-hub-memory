## 3 三条不因为"纯快"就放开的闸

写这条线时最容易被自己劝放的就是边界，所以逐条钉了用例：

1. **硬边界照旧**：付费禁测渠道 / 封存渠道 / 伪免费禁碰名单（`thinkingmachines/inkling` 等）/
   OR 当日全 0 价白名单 / 非文本输出，一条不放（用例 14）。
2. **人类裁决照旧**：`NON_GOAL`（V4 各代不考虑）与渠道裁决（魔搭只配 V4.1-Flash）对快线同样生效
   （用例 14b）。这条线是"不要能力"，不是"不要我定过的规矩"。
3. **隐私席不进快线**：`stealth/space-bunny-alpha` 就算全池最快也挡——测试/脚本流量内容不可控，
   属隐私红线（用例 17/17b）。
4. 速度也要证据：窗口内无有效 tok/s、成功实测 <3 条、可用率 <0.7 的一律不进（用例 15/16）。
   「不猜速度」和「不猜能力」是同一条纪律。

## 4 实现要点

- 策略层：`services/orchestration_policy.py` 加 `SPEED_CHAIN="fast"` / `SPEED_META` / `SPEED_PARAMS`
  （cap 8、n_ok≥3、rel≥0.7、单日换席预算 4、min_members 3）+ `speed_rank()` / `speed_admit()`。
  `speed_rank` 刻意用 raw tok/s 而不是百分位加权分——加权会让 TTFT 把更慢的席顶到前面，那不是"纯快"。
- 决策器：`scripts/auto_orchestrate.py` 加 `speed_pool` / `plan_speed_line` / `sync_speed_line`，
  在生产线事务之后独立一段执行，取数池 = 所有免费线（含 10-05 前的旧别名）+ fast 自己；
  日报加第 ⑪ 段（目标序 / 落选点名 / 出局逐条原因 / 本线闸 / 写入结果）。
- 写入口：`services/routes_writer.py` 新增 operation `speed_line_sync`，唯一调用方 `auto_orch`。
  mutator 内对 fast 之外所有链做 deepcopy 前后比对，触碰别链即整笔拒绝；
  空目标序只在"确有摘除理由"时允许落盘。
- 每日 12:15 的 `AutoSeatOrchestrate` 计划任务不用改，明天起自动带上这段。

## 5 验收

`scripts/orch_p0_acceptance.py` 24 项 → **55 项全 PASS**（新增 13~23 组共 31 项）。

夹具抓到两个我自己写的真 bug，都改了：

1. `plan_speed_line` 最初把"单日换席预算"同时套在**首次建线**上：cur 为空时 adds 就是全部目标席，
   8 > 4 永远触发"只重排不换席"→ 这条线永远建不起来（19 号用例抓到）。
   改为 bootstrap 不算换席，预算只管已有席的日常进出。
2. `need_write` 最初写成 `bool(final) and 序不同`：现有席全踩红线时目标就是空线，
   条件永假 → **红线的席永远摘不掉**（22d 抓到）。改为序不同即需写，
   "有没有理由清空"交给 `sync_speed_line` 判（无摘除理由的空目标一律不写）。
