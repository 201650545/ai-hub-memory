# MEMORY.md — devel-tools 稳定知识（长期语义记忆）

> 定位：本文件回答「**关于这个项目，我们已经确定了什么**」，不回答流水账。
> 与 STATE.md 的分工：STATE 回答「现在发生什么、下一步是什么」；MEMORY 回答「已确定的知识」。
> 与 ROUTER.md 的分工：ROUTER 是低语义路由索引（历史在哪里），MEMORY 是已提炼的稳定结论。
> 与 archive 的分工：历史**过程**进 archive，从过程中提炼出的**知识**留在这里。
> 维护：只有当某条经验被**多次**验证、或属架构级决定时才写入本文件；单次事件留在 STATE。
> 迁移意义：旧 STATE 条目之所以不能删，常因里面混着"事件 + 知识"。知识提炼到本文件后，事件部分才有条件进入 archive。

## 一、镜像站问诊（opencli / 问达宝 / GPT）

1. **发送成功的硬判据 = `userMsgs>=1` 且 URL 变为 `/c/<uuid>`**。仅凭脚本返回 `sent` 不算——历史事故正源于此（对着死标签空转，脚本返回成功但消息从未发出）。
2. **发送前探活是硬门槛**，不是异常后的补救。探活项：页面非 about:blank、编辑器可用、目标会话存在。
3. **等待提取必须用稳定性判据**，不能用固定时长：完成 = 连续两次 `len` 相同 且 `stop=false`。工具 `scripts/gpt_wait_extract.mjs`（首探 30s，发现内容后 10s，上限 14 次）。固定 150s 会抓到流式中间态导致存档丢内容（实测 150s 时仅 1449 字符、最终 3858）；固定 30s 同样会抓残缺。
4. **不能用 `assistantCount` 比较判断新回复**——baseline 若在发送后采集会含空占位，导致 `count > baseline` 永不成立。
5. **Extended 模式前 60s 常 `len=0`**，是思考期不是空回复；连续 6 次探测（约 180s）全空才判疑似故障并上报，不自动换模型兜底。
6. **会话寻址**：`gptreview` 不出现在 `opencli profile list`，但可直接寻址，不要据 profile list 否定其存在。
7. **在线判据看 `editor:true`**，不看 `interactive` 计数（`interactive:0` 只是 SPA 元素树未刷新）。
8. **账号在健康 Plus 池内轮转**，不要把任一账号变成永久首选（否则只是把单点从 vip-12 换成 vip-24）。「账号健康」与「当前 tab 健康」是两个维度；某实例连续失效即熔断换号，不反复救同一实例。
9. **问诊同频**：每轮问诊前必须把相关文档 commit + push 并验证 raw 可达（200）。未推送就引用会让 GPT 核验失败而中止作答（问题库 Q17）。
10. **实读令牌机制有效**：要求 GPT 原文引用仓库内嵌令牌，可验证它真的读了文件而非凭摘要作答。

## 二、网关 :3100 与 DSH（DeepSeek Harness）

1. **DSH 只传统一模型名（如 `fast`），实际路由与 fallback 顺序完全由网关决定**。改 `routing.fast.order` 即改后台顺序，DSH 界面无需任何改动。这是「前台稳定、后台动态」的核心机制。
2. **不要让 DSH 菜单跟随 `/v1/models` 实时/周期同步**——该列表随渠道健康在 158↔123 波动，会让菜单跟着网络抖动。正确层次：统一编排组配置变更时同步（已有 `sync_dsh_models()` 钩子挂在 `set_unified_model`/`delete_unified_model`），上游健康变化时不动 DSH。
3. `sync_dsh_models()` 依赖 **PyYAML**；解释器更换或升级后必须重装，否则 try/except 吞掉异常导致钩子静默失效。
4. 多引擎 AI 搜索跑在网关 **:3000**（不是 :3100）。

## 三、凭证与扣费边界

1. **credential_ref 可进入配置/控制平面；真实 secret 只留本地凭证信任域，不得进入 Git、记忆、日志。**
2. **判据「未泄漏凭证」的正确扫描范围** = Git 已跟踪文件 + `git log -p` 范围 + STATE.md + 转发日志（`secret_scan.py --tracked-only`）。全量工作树会命中 `channels.json`/`api_state.json`/`credentials.json` 等 **UNTRACKED+gitignored** 的设计内本地存储，属误报。
3. **「免费/收费」不能靠上游 `/models` 自证**——多数不返回价格字段，需依据厂商口径 + 人工确认。
4. Fast 编排的成员必须逐一核对实际模型名：免费档与收费档可能只差后缀（如 `agnes-2.5-flash` 免费 vs `agnes-2.5-pro` 收费）。

## 四、否定性判据的验证规范（GPT 阶段3 复核确立）

> 凡「未泄漏 / 未修改 / 零访问」这类**否定性判据**，必须配机器可验证的 scan / diff / count，**不能只写执行者结论**。单凭"我确认没有"一律判证据不足。

- 工具：`scripts/secret_scan.py`（`--tracked-only` 模式）
- 达标线：`finding_count=0` 且 `exit_code=0`
- 输出强制 redaction：只报范围与计数，绝不保存命中的秘密正文

## 五、版本与协同纪律

1. **禁 `git push --force`**；冲突一律 `pull --ff-only` → 失败则 `rebase` → 再失败则停下报告，不硬推。
2. 记忆仓是多 Agent 共享，改前先 `pull --ff-only`；SID 取当前最大号 +1 避免撞号。
3. **他人的未提交改动不代提交、不代回退**，保留原样直至其本人处理（除非用户明确授权二选一）。
4. 悬而未决的状态要了断——对他人未提交改动，"要提交就提交，不提交就取消"，不留中间态。
5. **动手前先查是否已有机制**，避免重复造轮子（教训：提议做 DSH 动态同步，实际 `sync_dsh_models()` 早已存在）。
6. 与 GPT 协作：我主执行、GPT 复盘。可质疑其方法但须有理有据；被有理有据地否决时应接受（教训：A 方案被否，避免了破坏核心机制）。
7. **封存的是上下文占用，不是信息本身。封存不是删除。** 冷记忆必须可通过 ROUTER 索引召回，否则等于永久丢失。
